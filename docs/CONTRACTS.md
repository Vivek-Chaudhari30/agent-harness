# CONTRACTS.md: frozen interfaces

**Status: frozen at the end of Phase 0. Read this before writing any code.**

Four agents build against these in parallel worktrees. That only works if nobody redefines a shape.
If you think a contract is wrong, write your proposal to `docs/contract-changes/<your-lane-id>.md`
and **keep building against the contract as written**. Do not edit this file outside the

Everything here lives in `src/schemas.py`. Nobody redefines these types locally.

## 0. Polarity convention (read this twice)

Two different words for the same axis, deliberately, because they answer different questions:

- `RuleResult.passed`: **True means the email obeyed the rule.**
- `Label.violated`: **True means the rule was broken.**

`violated == not passed`. This sign flip is the single most likely bug in the project, because
`score.py` compares one against the other. Convert at exactly one place, in `score.py`, in a named
function, with a unit test that would fail if the sign flipped. Do not convert anywhere else.

For every metric in `score.py`, **the positive class is "a violation is present."** So:

- true positive: grader says violated, ground truth says violated
- false positive: grader flags a violation the ground truth says is not real
- false negative: a real violation the grader missed

## 1. Core types (`src/schemas.py`)

```python
from dataclasses import dataclass, field
from typing import Literal, Callable, Any

RuleKind = Literal["deterministic", "semantic"]
Verdict  = Literal["deterministic", "semantic", "labeler", "human"]

@dataclass(frozen=True)
class Rule:
    id: str                      # stable slug, unique within an instruction set: "word_limit_90"
    instruction_set_id: str      # "is_01"
    source_instruction: str      # the original plain-English text, verbatim
    kind: RuleKind
    description: str             # one human-readable line, shown in the review sheet
    check_id: str | None = None  # deterministic only: key into rules.CHECKS
    params: dict[str, Any] = field(default_factory=dict)   # deterministic only: {"limit": 90}
    judge_prompt: str | None = None   # semantic only: a fully specified judge prompt template
    judge_prompt_sha: str | None = None  # sha256 of judge_prompt, for auditability

@dataclass(frozen=True)
class RuleResult:
    rule_id: str
    passed: bool                 # True == obeyed
    reason: str                  # one line. Required when passed is False. May be "" when passed.
    kind: RuleKind
    source: Verdict              # who produced this verdict

@dataclass
class Label:
    email_id: str
    rule_id: str
    violated: bool               # True == broken. Note the inverted polarity vs RuleResult.passed.
    reason: str
    kind: RuleKind
    confidence: Literal["high", "low"] = "high"
    reviewed: bool = False       # a human actually looked at this row
    overturned: bool = False     # the human disagreed with the model draft

@dataclass
class EmailRunResult:
    email_id: str
    instruction_set_id: str
    initial_results: list[RuleResult]     # PRE-repair. This is what score.py compares.
    repair_attempted: bool
    repaired_body: str | None
    final_results: list[RuleResult]       # post-repair, or identical to initial when none attempted
    status: Literal["pass", "pass_after_repair", "held"]
    still_failing: list[str]              # rule ids; empty unless status == "held"

@dataclass
class BatchRunResult:
    run_id: str
    config: dict
    emails: list[EmailRunResult]
    summary: dict                # n_emails, passed_first_try, passed_after_repair, held, adherence_rate
```

`EmailRunResult` and `BatchRunResult` serialize to the JSON in section 3.4 field for field. `Label`
serializes to the entries in section 3.3. Round-tripping through those loaders is a reasonable
test.

Rule id slugs are stable across runs. Never derive a rule id from list position: derive it from the
instruction content so that reordering an instruction set does not silently invalidate every label.

`judge_prompt` is a **compiled artifact**, not the raw instruction restated. It states the rule, what
counts as a violation, what does not, and asks for a single boolean plus a one-line reason. Compiling
"always reference something specific about their company" into a judge prompt that just repeats that
sentence is not compilation, and Lane A's review will reject it.

## 2. Function signatures

Each is owned by exactly one lane. Signatures are frozen; internals are not.

```python

def check_semantic_rule(email: str, rule: Rule) -> RuleResult: ...
```

## 3. JSON file schemas

Every file carries `"version": 1`. Every loader validates and raises on mismatch.

### 3.1 `fixtures/instruction_sets.json`: written in Phase 0

```json
{
  "version": 1,
  "sets": [
    {
      "id": "is_01",
      "label": "casual founder-led outbound, hard word cap",
      "sender_persona": "founder at a small workflow-automation company",
      "instructions": [
        "Never mention pricing.",
        "Keep it under 90 words.",
        "Do not ask a question in the first email.",
        "Always reference something specific about their company.",
        "No exclamation marks.",
        "Sign off with a first name and company name on separate lines."
      ]
    }
  ]
}
```

`instructions` are verbatim plain English. Rule ids are derived from them at compile time, not
stored here.

### 3.2 `fixtures/emails.json`: written by Lane C

```json
{
  "version": 1,
  "emails": [
    {
      "id": "em_001",
      "instruction_set_id": "is_01",
      "recipient_context": {
        "company": "Acme Robotics",
        "industry": "industrial automation",
        "detail": "recently opened a second assembly line in Ohio"
      },
      "body": "...",
      "planted_violations": ["word_limit_90", "no_implied_pricing"],
      "difficulty": "clean | single | multiple | borderline",
      "generation": {
        "mode": "compliant | violating",
        "model": "<resolved model id>",
        "created_at": "2026-09-04T18:22:11Z"
      }
    }
  ]
}
```

`planted_violations` is generation metadata. It is **never** read by `checker.py`, `labeler.py`, or
`score.py`. Only `fixtures.py` writes it and only a human reads it, to sanity-check coverage.

### 3.3 `fixtures/labels_model_draft.json` and `labels_ground_truth.json`: Lane C, then a human

Same schema. The second is the first after review.

```json
{
  "version": 1,
  "provenance": {
    "kind": "model_draft | human_reviewed",
    "model": "<resolved model id>",
    "labeler_prompt_sha": "<sha256 of the labeler prompt>",
    "reviewed_at": "2026-09-04T21:40:00Z",
    "reviewer_note": "free text"
  },
  "labels": [
    {
      "email_id": "em_001",
      "rule_id": "word_limit_90",
      "violated": true,
      "reason": "97 words, seven over the cap.",
      "kind": "deterministic",
      "confidence": "high | low",
      "reviewed": false,
      "overturned": false
    }
  ]
}
```

The label set is **complete**: exactly one label per (email_id, rule_id) pair for every rule in that
email's instruction set. A missing pair is an error, not an implicit pass. `score.py` must raise on
an incomplete ground truth set rather than silently scoring a subset, because silently scoring a
subset is how a grader reports 100% recall on the rules it happened to cover.

`reviewed` is set true by the review tool for every pair a human actually looked at. `overturned` is
true where the human disagreed with the draft. Both are reported in the README: the overturn rate is
a real and interesting number, since it says how far a blind model read is from a careful human one.

### 3.4 `runs/<run_id>.json`: the grader's output, written by Integration

```json
{
  "version": 1,
  "run_id": "2026-09-04T22-05-13Z",
  "config": {"model": "...", "writer_model": "...", "cache": true},
  "emails": [
    {
      "email_id": "em_001",
      "instruction_set_id": "is_01",
      "initial_results": [{"rule_id": "...", "passed": false, "reason": "...", "kind": "...", "source": "..."}],
      "repair_attempted": true,
      "repaired_body": "... or null",
      "final_results": [{"...": "..."}],
      "status": "pass | pass_after_repair | held",
      "still_failing": ["rule_id"]
    }
  ],
  "summary": {
    "n_emails": 50,
    "passed_first_try": 31,
    "passed_after_repair": 16,
    "held": 3,
    "adherence_rate": 0.94
  }
}
```

`initial_results` is the pre-repair verdict set. **This is the field `score.py` compares against
ground truth**, not `final_results`. Grading the post-repair email against labels written for the
pre-repair email is a category error that would inflate the grader's apparent accuracy.

`status` is exactly three values. There is no fourth.

### 3.5 `runs/<run_id>.metrics.json`: written by Lane D

```json
{
  "version": 1,
  "run_id": "...",
  "adherence": {
    "n_emails": 50, "passed_first_try": 31, "passed_after_repair": 16,
    "held": 3, "adherence_rate": 0.94,
    "holds": [{"email_id": "em_007", "still_failing": ["word_limit_90"], "reason": "..."}]
  },
  "grader": {
    "positive_class": "violation_present",
    "aggregate":     {"tp": 0, "fp": 0, "fn": 0, "tn": 0, "precision": 0.0, "recall": 0.0, "f1": 0.0, "support": 0},
    "by_kind":       {"deterministic": {"...": 0}, "semantic": {"...": 0}},
    "by_rule":       {"word_limit_90": {"...": 0}},
    "n_labels": 300,
    "n_reviewed": 300,
    "n_overturned": 24
  }
}
```

Adherence and grader accuracy are separate objects and are never averaged together. Reporting a
single blended number hides which failure mode dominates, which is exactly the thing this project
exists to expose.

## 4. Rules every lane obeys

1. **Structured output only.** All model calls go through `model_client.call_json` with a schema.
   Free-text JSON parsing is banned.
2. **One semantic rule per model call.** No batching.
3. **Deterministic checks are pure.** `CHECKS` callables take `(text, params)` and return
   `(bool, str)`. No network, no file I/O, no clock, no randomness. They must be unit-testable
   without an API key.
4. **No hardcoded model IDs** in application logic. Read from `Config`.
5. **Every model call is cached** by default. `temperature=0`.
6. **Tests pass under `MODEL_PROVIDER=fake`** with no API key set. If your lane's tests need a key,
   your lane is not done.
7. **Do not edit files you do not own.** Ownership is in `docs/AGENT_LANES.md`. `pyproject.toml`,
   the `Makefile`, `schemas.py`, `config.py`, `model_client.py`, `writer.py`, and
   `instruction_sets.json` are Phase 0 property and are read-only for every lane.
8. **Commit trailer** on every commit: `Conductor-Lane: <your-lane-id>`.
